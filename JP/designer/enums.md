# 列挙型（enum）

「受注 / 出荷済 / 完了」のような**決まった選択肢**を、プロジェクト全体で 1 回だけ定義して、複数の SelectField やスクリプトから共通で使う仕組みです。

選択肢を各 SelectField の `Candidates` に直接書くと、同じ選択肢が複数のモジュールに散らばり、変更漏れや表記の揺れが起きやすくなります。同じ選択肢を 2 か所以上で使う場合や、スクリプトで選択された値によって処理を分ける場合は、列挙型にしておくと管理が楽になります。

---

## 列挙型を作る

1. デザイナのソリューションツリーを右クリックし、**列挙型追加** を選ぶ
2. 列挙型の名前を付ける
3. エディタで **値の型** を選び、メンバー（**名前** / **値** / **表示名**）を追加する

列挙型は 1 つにつき 1 ファイルとして、デザインプロジェクトの `Enums` フォルダに `{名前}.enum.json` で保存されます。

### 値の型

| 値の型 | 内容 |
|---|---|
| `String`（既定） | 文字列の値を保存する |
| `Number` | 数値を保存する。メンバーの値は**整数だけ**（小数はデザインチェックでエラー）。DB の列は整数型でよい |

### メンバーの項目

| 項目 | 内容 | 省略したとき |
|---|---|---|
| **名前** | スクリプトから参照するときの名前。スクリプトの識別子として使える名前（`if` `class` などの予約語は不可） | 省略不可 |
| **値** | DB に保存される値 | 名前がそのまま値になる |
| **表示名** | 画面の選択肢に表示される文字 | `Number` の場合は名前、`String` の場合は値（値も省略なら名前）を表示 |

例（`OrderStatus`、値の型 `String`）:

| 名前 | 値 | 表示名 | 保存される値 / 表示 |
|---|---|---|---|
| `Received` | `1` | 受注 | `1` / 受注 |
| `Shipped` | （省略） | （省略） | `Shipped` / Shipped |
| `Closed` | （省略） | 完了 | `Closed` / 完了 |

- DB に保存されるのは**値だけ**です（列挙型の名前は保存されません）。すでにデータがあるテーブルに後から列挙型を導入しても、値が一致していれば表示名で表示されます
- 列挙型の名前は、モジュール・PageFrame の名前と重複できません

---

## SelectField で使う

SelectField の **EnumName**（列挙型名）に列挙型の名前を指定すると、そのメンバーが選択肢になります。選択肢には表示名が表示され、選んだメンバーの値が保存されます。

選択肢の決まり方は **EnumName > Candidates > モジュールの検索** の優先順です。EnumName を指定すると Candidates は使われません。

> RadioGroupField では使えません（選択肢は配置した RadioButtonField で決まるため）。

---

## スクリプトから使う

列挙型の名前とメンバー名で参照できます。値は**保存される値（文字列）**です。

```csharp
Status.Value = OrderStatus.Received;          // 値 "1" が入る
if (Status.Value == OrderStatus.Closed) { }   // 比較も値で行われる
Status.SearchValue = OrderStatus.Shipped;     // 検索条件の値にも使える
```

- 型としても書けます（`OrderStatus s = OrderStatus.Received;`、関数の引数・戻り値、`foreach` の変数など）。実行時の中身は文字列（保存される値）です
- EnumName を指定した SelectField の `Value` / `SearchValue` に、列挙型にない値の文字列を直接代入・比較すると、デザインチェックでエラーになります（空文字・`null` は「未選択」として使えます）
- モジュールに列挙型と同じ名前のフィールドがあると、スクリプトではフィールドが優先されます（デザインチェックが知らせます）

---

## 名前の変更

列挙型の名前やメンバー名は、ツリーの右クリックメニューの **名前を変更**、またはエディタでメンバー名を変更して変えます。SelectField の EnumName やスクリプト内の参照も一緒に書き換わります。

**値を省略していたメンバーの名前を変えると、変更前の名前が値として固定されます。** DB にすでに保存されている値との対応を保つためです（表示名も省略していた場合、表示は変更前の名前のままになります）。

---

## C# で定義した enum を公開する

カスタムフィールドを作る場合など、C# の enum に `[DesignEnum]` 属性を付けると、列挙型のファイルを作らなくても列挙型と同じように使えます（SelectField の EnumName、条件設定の値の候補、スクリプトからの参照）。

```csharp
[DesignEnum]                                          // 名前を省略すると型名が列挙型の名前になる
public enum ApprovalFlowStatus
{
    [DesignEnumMember(DisplayText = "$ApprovalFlowStatus_InProgress")]
    InProgress,
    Completed,
}

[DesignEnum(Name = "TaskPriority", ValueType = EnumValueType.Number)]
public enum TaskPriorityEnum { Low = 1, High = 3 }
```

- 保存される値は、`String`（既定）ではメンバー名（`[DesignEnumMember(Value = ...)]` で変更可）、`Number` では enum の数値です
- 表示名に `$キー` と書くと、enum を定義したアセンブリのリソースから表示名を読み込みます（カスタムフィールドの表示名と同じ仕組みで、言語ごとに切り替えられます）
- C# のコードから保存される値が必要なときは `ToDesignValue()` 拡張メソッドを使います（例: `ApprovalFlowStatus.InProgress.ToDesignValue()`）
- デザイナでは読み取り専用で、名前の変更の対象になりません。メンバー名を変えると DB に保存済みの値と合わなくなるので注意してください
- ソリューションツリーには既定では表示されません。表示するには Enums を右クリックして **C# から公開されている enum を表示** をオンにします（表示しなくても使えます）
- 同じ名前の列挙型ファイルがあると、デザインチェックで名前の重複エラーになります

---

## デザインチェック

次のような誤りはデザインチェックで検出されます。

- 列挙型の名前・メンバー名が識別子として使えない、または重複している
- メンバーの値・表示名が重複している
- 値の型が `Number` なのに整数でない値がある
- SelectField の EnumName に存在しない列挙型を指定している
- スクリプトで列挙型にない値を使っている
