# 1.3.19 〜 1.3.25

1.3.19 から 1.3.25 までに入った、既存アプリの動作が変化する可能性がある項目の一覧です。
各項目の見出しに、変更が入った版を記載しています。

---

## 1. 列挙型と同じ名前の C# の enum を同じものとして扱わなくなりました (1.3.19)

デザインの列挙型と、スクリプトから使える C# の enum が同じ名前のとき、両者を同じものとして扱う決まり (1.3.15 で導入) を廃止しました。

```
変更前: 同じ名前のデザインの列挙型と C# の enum は、同じものとして扱われていた
変更後: 同じ名前はデザインチェックで名前の重複エラーになる
        スクリプトでは通常の名前の解決に従い、C# の enum が使われる
```

C# 側で定義している enum をデザインでも使いたい場合は、列挙型のファイルを削除し、C# の enum に `[DesignEnum]` 属性を付けて公開してください。定義が 1 つで済みます。
→ [列挙型（enum）](../designer/enums.md#c-で定義した-enum-を公開する)

---

## 2. スクリプトから .NET へ渡す小数は、整数へ切り捨てで変換されるようになりました (1.3.21)

スクリプトの小数を整数に変換するときの決まりは「切り捨て (0 方向)」で、代入・キャスト・スクリプト関数の引数ではこの決まりに従っていました。
ところが、スクリプトから .NET のメソッド等へ値を渡すときだけ四捨五入に近い丸めになっていたため、すべて切り捨てに統一しました。

対象は次のとおりです。

- .NET のメソッド・コンストラクタの整数の引数
- インデクサの引数・配列のインデックス (`list[1.9]` は `list[1]`)
- 配列のサイズ (`new int[2.9]` は要素数 2)
- .NET のオブジェクトのプロパティ・配列の要素への代入

```csharp
"abcdef".Substring(1.9);
// 変更前: "cdef"  (2 に丸められていた)
// 変更後: "bcdef" (1 に切り捨て。int x = 1.9 と同じ)
```

整数を受け取る引数などに小数の計算結果を渡していて、端数が 0.5 以上のときに結果が 1 変わります。
丸めたい場合は `Math.Round(x)` で丸めてから渡してください。
小数を受け取るオーバーロードがあるメソッド (`Math.Max(1.9, 0)` など) は、そちらが選ばれるため影響しません。

あわせて、計算結果の数値を .NET のコンストラクタに渡すと「コンストラクタが見つからない」で失敗していた問題 (`new DateTime(year, month, day)` で `day` が計算結果の場合など) も修正されています。

## 3. ClearError が子の Field のエラーもクリアするようになりました (1.3.21)

子のモジュールを持つ Field の `ClearError()` が、子の Field のエラーもまとめてクリアするようになりました。

```
変更前: ClearError() はその Field 自身のエラーだけをクリアしていた
変更後: ListField (DetailList / TileList を含む) は全行の Field のエラーも、
        ModuleField は子モジュールの Field のエラーも、
        SearchField は検索条件の Field のエラーもクリアする
```

一覧や埋め込みモジュールの `ClearError()` を呼んだ後も、行や子モジュールのエラー表示が残ることを前提にしていたスクリプトは動作が変わります。

## 4. スクリプトから一覧に入れたデータが、一覧の編集設定に関係なく反映されるようになりました (1.3.25)

`SetJsonObject` などでモジュールにデータを入れるとき、含まれる一覧 (ListField) のデータは、
一覧の `CanCreate` / `CanUpdate` / `CanDelete` がすべてオンでないと反映されず、黙って捨てられていました。
これらは画面の操作を許可するかどうかの設定なので、スクリプトからのデータの反映には関係しないように変更しました。

```
変更前: CanCreate / CanUpdate / CanDelete のどれかがオフの一覧には、スクリプトから入れたデータが反映されなかった
変更後: 設定に関係なく反映される
```

なお、1.3.21 〜 1.3.23 では、同じ条件の一覧に `AddRow` / `AddRows` / `InsertRow` / `InsertRows` で追加したデータも捨てられていました (1.3.21 で入った不具合)。これも 1.3.25 で修正されています。

[モジュールコピーボタン](../fields/CopyModuleButton.md) でのコピーでは、従来どおり編集できない一覧 (`CanCreate` / `CanUpdate` / `CanDelete` のどれかがオフの参照用の一覧) の行はコピーされません。

## Extras・テンプレート側の変更

次の項目は Codeer.LowCode.Blazor 本体の版ではなく、拡張ライブラリ [Codeer.LowCode.Blazor.Extras](https://github.com/Codeer-Software/Codeer.LowCode.Blazor.Extras) とアプリのテンプレート (ホストアプリ) 側の変更です。
Extras を更新するときは、あわせてサーバー側の結線を確認してください。

- **メール送信**: Extras 0.12.0 で、スクリプトから送信する `MailService` と、サーバーの旧メール設定を削除しました。MailField / BulkMailField に置き換えてください → [Mail (Extras)](https://github.com/Codeer-Software/Codeer.LowCode.Blazor.Extras/blob/main/docs/Mail.md#050-のメール-api-から移行する)
- **ファイルの保存先**: テンプレートの appsettings は保存先の種類ごとのセクション (`FileSystemStorages` / `AzureBlobStorages` / `S3Storages`) になりました。従来の `FileStorages` の形式もそのまま読み込まれます → [FileStorage (Extras)](https://github.com/Codeer-Software/Codeer.LowCode.Blazor.Extras/blob/main/docs/FileStorage.md)
- **一括ファイル入出力**: Extras のスクリプトの一括ファイル入出力 (加工済みのデータのファイル出力・ファイルの解析・一括保存) を使うには、サーバーの `api/module_data` に `list_file_by_data` / `parse_file` / `bulk_submit` の受け口が必要です。新しいテンプレートには最初から入っています → [BulkFileTransfer (Extras)](https://github.com/Codeer-Software/Codeer.LowCode.Blazor.Extras/blob/main/docs/BulkFileTransfer.md)
